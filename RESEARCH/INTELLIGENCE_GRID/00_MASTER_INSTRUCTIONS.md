# BAD-D Intelligence Grid — AI Research Control

## Mission
Research the next intelligence layer for BAD-D before implementation.

All AI agents working on this repository must treat GitHub as the source of truth for this research lane. Do not depend on instructions pasted into a chat when the repository contains the current instructions.

## Core hypothesis
The musical grid is not merely a beat grid. It is an intelligence layer describing changing musical structure, expectation, disruption, release, and possible human response.

A dominant 4/4 interpretation must never erase local meter changes or unusual structural events.

## Research order
Run these research passes in order:

1. What the Intelligence Grid must represent.
2. The 4/4 bias and changing meter.
3. Musical structure → human response.
4. DJ decision intelligence.
5. Adversarial reality check.
6. Map the validated research onto BAD-D.

## Rules
- Research before implementation.
- Do not modify production code during research.
- Do not force uncertain audio analysis into false certainty.
- Separate measured audio facts, perceptual interpretations, human-response hypotheses, and crowd-response observations.
- Never collapse everything into a single danceability score.
- Preserve uncertainty and competing interpretations.
- Treat meter as time-varying unless evidence shows otherwise.
- A structurally unusual event may be more informative than the dominant pattern.
- Human testing remains authoritative for perceptual claims.
- Record sources, datasets, algorithms, limitations, and reproducible experiments in GitHub.
- Every AI must read this folder before beginning work in this lane.

## Output
Each research pass must leave a written artifact in this folder and link sources directly. Do not merely report findings in chat.

## Human command
When Daniel says "go", the AI should first read this control file and the next uncompleted research pass, then work from GitHub.
