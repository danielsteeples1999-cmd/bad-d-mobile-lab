# tools/grid-meter: metrical fixtures + tracker scoring

Reusable harness built for **GRID-METER-001**. It answers: *does a beat / downbeat tracker keep the right bar phase when the meter does something other than steady 4/4, and does its confidence warn when it doesn't?*

| File | Purpose |
|---|---|
| `fixtures.py` | Deterministic synthetic drum+bass+pad fixtures from a **bar plan** (list of bar lengths in beats), with exact ground truth. Includes the **fixture acceptance gate** (`accept()`): it checks that the rendered audio actually contains the truth (matched-filter kick detection, determinism, no clipping). |
| `trackers.py` | Adapters with one interface: madmom RNN+DBN (`beats_per_bar=[4]`, `[2,3,4]`) and Beat This! (`final0`, minimal and DBN post-processing). |
| `evaluate.py` | Scoring against exact truth with a fixed 70 ms window (never tuned). Reports: beat/downbeat F, per-bar estimated length histogram, downbeat-phase histogram, **longest run of missed downbeats** (direction-neutral) with beat recall inside it, deviation-local metrics, and **confidence AUC** (does the model's own downbeat activation separate its correct from its wrong downbeats?). |
| `run.py` | Bounded matrix runner (≤ 24 fixtures × 4 systems). WAVs are never written to disk; results go to JSON (`grid-meter-results/1.0.0`). |
| `summarize.py` | Compact markdown tables from a results JSON. |
| `detect.py` · `run_detect.py` · `score_detect.py` | GRID-METER-002 per-bar meter-error detectors (D1 in-bar activation contrast, D2 cross-decoder disagreement, D3 = either), runner, and scorer applying the pre-registered criteria. |
| `test_grid_meter.py` | Self-tests, including **attacks on the gate**: an extra kick inserted into the audio, and a beat label moved by 30 ms in the truth. Both must be rejected. |

```bash
python3 -m venv /tmp/gridenv

/tmp/gridenv/bin/pip install numpy scipy soundfile soxr einops rotary-embedding-torch tqdm mir_eval \
    "beat_this @ git+https://github.com/CPJKU/beat_this" "madmom @ git+https://github.com/CPJKU/madmom"
cd tools/grid-meter
/tmp/gridenv/bin/python test_grid_meter.py              # self-tests (no models needed)
/tmp/gridenv/bin/python run.py out.json                  # full matrix, ~12 min on 4 CPU cores
/tmp/gridenv/bin/python summarize.py out.json
```

## Adding a fixture

Add a bar plan to `PLANS` in `fixtures.py` (or a constant-meter variant to `VARIANTS`; `render_named()` handles both). For example, `[4]*8 + [3] + [4]*8` inserts a single 3-beat bar. The truth is generated by construction. A fixture that fails `accept()` is rejected, never "tolerated".

## Known limits
- The fixtures are synthetic and very clean. Passing them is necessary but not sufficient for real music.
- The downbeat cues are harmonic changes (1 chord per bar) and crashes on phrase starts. Music with weaker cues will be harder.
- Mobile/on-device execution is not covered. These are desktop Python reference implementations.
